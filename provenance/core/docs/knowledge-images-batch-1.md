# Knowledge Images — Batch 1

Date: 24 October 2026. Local content-only image tranche.

Thirty existing ingredient reference pages gain their first photograph. Image-bearing knowledge pages increase from 19 to 49; 862 of the 911 independently enrichable pages remain without images. All 911 retain their existing editorial enrichment. No identities, aliases, recipes, source text, parser behaviour or renderer styling changed.

## Selection and licensing

The first batch favours recognisable produce and herbs. Each selected Commons image has image-specific licence metadata, creator credit, source-page and original-file URLs, and an acquisition URL recorded in the [decision ledger](knowledge-images-batch-1.json). Credits render visibly through the existing reference renderer and are also retained in [image attribution](../assets/references/ATTRIBUTION.md). CC BY-SA derivatives retain their source licence; photographs are not relicensed under the knowledge-data CC0 grant. Public-domain USDA images retain their agency/source credit; the green-bean source does not identify an individual photographer.

All selected full frames were visually inspected. Rejected search candidates included leek flowers, a musician named Scallions, non-bell peppers, and ambiguous bean imagery. No restricted noncommercial or GFDL-only option was selected. Existing 19 images and their credits remain intact.

## Optimisation

Progressive JPEG, quality 82, optimised encoding, no crop, maximum 960 pixels on the longest edge, no upscaling. Embedded metadata is removed while attribution is retained separately. New image bytes: **3,912,715** (about 3.91 MB; average 130 KB). The largest is below 300 KB. Original-resolution masters and rejected candidates are not added to the repository.

## Preservation and regression coverage

The ledger pins all canonical file hashes, the complete prior enrichment registry and the resource registry. A focused test removes only these 30 newly introduced hero fields to compare the complete historical registry; each new hero is independently checked against its exact metadata and image checksum. Earlier batch snapshot tests reuse that narrow historical projection rather than changing historical hashes. Existing optional-image, escaping, attribution and route tests remain active.

## Validation

- Core: type checking, build, **1,185 tests**, documentation check (28 documents) and quality audit passed. The 14 samples retain zero parser errors; 10 existing undeclared-known-thing findings remain unchanged.
- Corpus: **395 tests** and **490/490** recipe parses passed. No Corpus files changed.
- Site: type checking, **128 tests**, site build and site validation passed: 1,667 pages, 1,873 files, 66,511 internal links and 2,450 fragments.
- Clean tracked-source export: public-source audit passed, 1,278 files, 969 knowledge entries and 14 samples. Seven unrelated user-owned files and ignored archives were excluded and untouched.
- Ordinary localhost preview: every one of 1,667 generated HTML pages matched its built bytes. All 30 new asset URLs returned HTTP 200, image/jpeg and exact SHA-256 checksums; page captions, source links, licence links and derivative notices matched.
- Visual: all 30 derivatives inspected in contact sheets. In-app browser spot-check of the carrot page confirmed the photograph, caption and expanded credit/licence details. This is not a full browser suite or mobile/theme matrix.
- Preservation and git whitespace checks passed. Only image metadata/assets, attribution, reports and narrowly related tests changed. Core and Site receive local commits on codex/knowledge-images-batch-1; no merge, push, publication or deployment.

A temporary HTTP audit script initially shadowed Python's standard http module; renaming that temporary helper fixed the audit. No product-code change was needed.
